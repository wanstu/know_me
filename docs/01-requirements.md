# know_me 需求分析

状态：Phase 1 完成  
日期：2026-09-18

## 1. 产品定位

know_me 不是单一“博客模板”，而是一个个人数字入口。它同时承担：

- 浏览器新标签页 / 起始页；
- 公开个人主页；
- 公开个人博客；
- 私有管理后台。

四者共用同一套账号、主题、媒体资源和站点配置，但公开程度不同。

## 2. 核心用户

### 2.1 站长

主要行为：

- 每天把 /start 设置为浏览器主页；
- 快速搜索和打开常用链接；
- 增删改链接、分组、文件夹；
- 从 iTab 导入现有导航数据，也能随时导出回 iTab 兼容格式；
- 写 Markdown 博客，上传图片，预览、保存草稿、发布；
- 修改个人主页、主题、背景、社交链接；
- 在后台集中管理全部内容。

### 2.2 访客

主要行为：

- 访问个人主页；
- 浏览博客列表；
- 搜索文章；
- 按标签 / 分类 / 归档查看内容；
- 阅读文章并复制代码、跳转目录、查看上一篇/下一篇。

## 3. 模块需求

### 3.1 浏览器起始页

参考图 1 的核心结构，但减少视觉噪音。

必须支持：

- 时间、日期、搜索框；
- 搜索引擎切换；
- 链接分组；
- 链接卡片；
- 大小卡片；
- 文件夹；
- 图标 / 文字图标；
- 自定义颜色；
- 拖拽排序；
- 快速新增、编辑、删除；
- 链接搜索；
- 自定义壁纸 / 渐变背景；
- iTab 数据导入与导出；
- 导入预览、合并、覆盖三种策略；
- 移动端基本可用。

建议支持：

- 最近访问 / 常用排序；
- 键盘快速搜索；
- 搜索框命令前缀；
- 卡片快捷菜单；
- 备份快照；
- 每个链接/文件夹可设置“公开 / 私有”。

### 3.2 博客用户端

必须支持：

- 首页文章列表；
- 文章详情；
- 标题 / 正文全文搜索；
- 分类、标签；
- 归档；
- Markdown 渲染；
- 代码高亮；
- 自动目录；
- 上一篇 / 下一篇；
- 响应式阅读体验；
- RSS；
- sitemap；
- 基础 SEO / Open Graph。

Markdown 能力建议覆盖：

- GFM；
- 表格；
- 任务列表；
- 脚注；
- 代码块；
- 数学公式；
- Mermaid；
- 图片说明；
- 标题锚点；
- 可选的提示块 / callout。

### 3.3 博客管理端

必须支持：

- 登录 / 退出；
- 文章列表；
- 新建 / 编辑 / 删除；
- 草稿 / 发布；
- Markdown 编辑器；
- 编辑 + 预览分栏；
- 自动保存；
- slug；
- 摘要；
- 封面；
- 标签 / 分类；
- 发布时间；
- 媒体上传与复用。

强功能方向：

- 修订历史；
- 定时发布；
- 置顶；
- SEO 单独配置；
- 草稿预览链接；
- 批量操作；
- 快捷键；
- 文章导入 / 导出 Markdown。

### 3.4 个人主页

参考图 2 的“沉浸背景 + 玻璃卡片”结构，但统一到 know_me 的视觉体系。

内容建议：

- 头像 / Logo；
- 名称；
- 一句简介；
- 当前时间 / 日期；
- 一句短句；
- 博客、起始页、项目、关于等入口；
- 社交账号入口；
- 可选天气（后续，不作为首版依赖）。

主页重点不是堆信息，而是做“访问 know_me 的总入口”。

### 3.5 管理后台

统一管理：

- 总览；
- 博客；
- 分类 / 标签；
- 媒体；
- 起始页；
- 个人主页；
- 外观；
- iTab 导入导出；
- 站点设置；
- 登录与安全；
- 备份恢复。

## 4. 权限与隐私

起始页很可能包含本地地址、测试环境、工作后台等链接，因此默认不能把“浏览器主页”和“公开个人主页”混为一谈。

建议：

- /：公开个人主页；
- /blog：公开博客；
- /start：默认需要登录，可在设置中改成公开；
- /admin：必须登录；
- 单个导航项仍有 visibility 字段，可在公开 start page 模式下隐藏私有项。

## 5. 非功能需求

### 性能

- 起始页首屏应非常快；
- 页面避免依赖大量第三方脚本；
- 图片自动生成多尺寸；
- Markdown 文章读取尽量走服务端渲染和缓存。

### 安全

- 密码只保存强哈希；
- Session 使用 HttpOnly / Secure / SameSite Cookie；
- 管理端写操作做 CSRF 防护；
- Markdown 禁止任意危险 HTML；
- 上传文件做类型与大小检查；
- 所有外部链接输出前进行协议校验；
- iTab 导入不直接执行任何数据中的脚本或 HTML。

### 可维护性

- 公开站点、起始页、后台共享设计系统；
- 导入层和内部数据模型解耦；
- Markdown 源文件始终可以导出；
- 数据库迁移可版本化；
- 支持 Docker 和普通 Node 部署。

## 6. MVP 边界

第一版应先把“每天能用”做出来：

1. 登录；
2. 个人主页；
3. 起始页 CRUD + 拖拽；
4. iTab 导入 / 导出；
5. 博客列表 / 详情 / 搜索；
6. Markdown 编辑 / 预览 / 发布；
7. 分类标签；
8. 主题与背景；
9. 基础备份。

评论、访客账号、多作者、复杂统计、天气、第三方 OAuth 不阻塞首版。

## 7. 验收标准

### 起始页

- 能导入提供的 iTab 备份；
- 分组、文件夹、链接层级不丢失；
- 图标、颜色、大小尽量还原；
- 修改后可导出为 iTab 可识别的 JSON 结构；
- 页面加载后可以在极少交互内完成搜索或打开链接。

### 博客

- 管理端可以完整写一篇 Markdown 文章并发布；
- 访客可以搜索并打开文章；
- 代码块、目录、图片、标签均正常；
- 草稿不会出现在公开站点。

### 个人主页

- 桌面与手机都能保持清晰布局；
- 入口卡片可以从后台配置；
- 不与起始页私有链接发生权限泄漏。
