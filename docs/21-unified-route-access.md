# Know Me 统一页面访问权限

## 规则

Go Native 服务端统一验证以下内置页面及其公开数据接口；仓库中的 Next.js / Docker 兼容运行时也在服务端页面、文章元信息生成和 RSS 输出前执行相同的访问规则：

| 内置页面 | URL | 同步受保护的接口 |
| --- | --- | --- |
| Start | `/start` | `/api/navigation/public` |
| Blog | `/blog`、`/blog/*` | `/api/blog/*` |
| RSS | `/feed.xml` | RSS 本身，且不得超过 Blog 的访问范围 |

后台 `/admin/*` 及后台 API 始终要求登录，不受主页入口设置覆盖。主页 `/` 和登录页 `/login` 保留公共访问，以避免配置后无法登录。媒体文件与外部站点不是这里的路由权限范围。Next.js 版博客被限制时，文章元信息与公开 sitemap 也不会披露受限文章。

- **公开访问**：登录及未登录均可访问。
- **仅登录访问**：匿名请求页面重定向登录，API 返回 401。
- **仅未登录访问**：登录用户直接访问页面或公开 API 返回 403。
- **禁用**：页面、API 均返回 404。

访问规则保存在原有站点设置的 `routeAccess` 字段中，不新建权限表，也不依靠前端隐藏控件作为安全防护。RSS 的实际可访问性必须同时满足 RSS 和 Blog 两条规则。

## 后台入口

在「站点设置 → 链接与项目 → 页面访问权限」统一修改；Start 页自身不再提供第二个公开开关。主页快捷标签及主页入口均保留独立的「显示条件」，只决定首页是否显示。内置 Start、Blog、RSS 的页面权限以「页面访问权限」为准：隐藏一个入口不会使目标页面不可访问；反之，即使入口显示，受限页面也无法通过直接输入 URL 绕过校验。Know Me 无法控制外部网站的访问权限。

对旧 `startPublic` 开关映射到 Start 页面访问权限；旧快捷标签和主页入口的显示条件继续保持原样，**不自动升级为页面权限**。旧版隐藏 Blog 标签绝不能使整站 Blog 变为禁用。新配置由 `routeAccess` 独立管理，保留显示与授权两层职责。

## 验证

`go test ./...` 会验证匿名 / 登录状态下的页面直接访问、公开 API、RSS 对 Blog 权限的继承，以及原有导航及站点设置兼容性。前端验证使用 `npm run typecheck` 和 `npm run native:web:build`；Next.js/Docker 兼容构建使用 `npm run build`。对有权限差异的 RSS，响应不可缓存。

上线前建议使用正常浏览器与无痕窗口分别验证，并通过开发者工具直接请求受控接口，不只检查按钮有没有隐藏。
