# Know Me 统一页面访问权限

## 规则

Go 服务端统一验证以下内置页面及其公开数据接口：

| 内置页面 | URL | 同步受保护的接口 |
| --- | --- | --- |
| Start | `/start` | `/api/navigation/public` |
| Blog | `/blog`、`/blog/*` | `/api/blog/*` |
| RSS | `/feed.xml` | RSS 本身，且不得超过 Blog 的访问范围 |

后台 `/admin/*` 及后台 API 始终要求登录，不受主页入口设置覆盖。主页 `/` 和登录页 `/login` 保留公共访问，以避免配置后无法登录。媒体文件与外部站点不是这里的路由权限范围。

- **公开访问**：登录及未登录均可访问。
- **仅登录访问**：匿名请求页面重定向登录，API 返回 401。
- **仅未登录访问**：登录用户直接访问页面或公开 API 返回 403。
- **禁用**：页面、API 均返回 404。

访问规则保存在原有站点设置的 `routeAccess` 字段中，不新建权限表，也不依靠前端隐藏控件作为安全防护。RSS 的实际可访问性必须同时满足 RSS 和 Blog 两条规则。

## 后台入口

在「站点设置 → 链接与项目 → 页面访问权限」统一修改；Start 页自身不再提供第二个公开开关。主页快捷标签及主页入口指向 Start、Blog、RSS 时使用相同规则。独立外部 URL 只能设置在主页是否展示，无法由 Know Me 控制目标网站的访问权限。

对旧 `startPublic` 和旧主页入口显示条件进行兼容：旧配置会映射为新权限，写入新设置时使用统一权限作为内置页面唯一权威，保留外部链接的独立可见状态。

## 验证

`go test ./...` 会验证匿名 / 登录状态下的页面直接访问、公开 API、RSS 对 Blog 权限的继承，以及原有导航及站点设置兼容性。前端验证使用 `npm run typecheck` 和 `npm run native:web:build`。

上线前建议使用正常浏览器与无痕窗口分别验证，并通过开发者工具直接请求受控接口，不只检查按钮有没有隐藏。
