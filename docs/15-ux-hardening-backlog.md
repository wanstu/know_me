## P0：交互正确性与全局一致性

### 1. 全局 Session 状态
- 当前首页、Blog 等公开页不统一读取 Session，登录后顶部导航仍可能显示“登录”。
- 在 App 层统一加载并缓存当前 Session。
- SiteHeader 统一使用全局登录态。
- 登录后显示“后台”，未登录显示“登录”。
- 后台任意 API 返回 401 时，统一跳转到：
  - `/login?next=<current path + query>`
- 避免各页面自行重复处理认证失败。

验收：
- 登录后访问首页 / Blog / Start，顶部状态一致。
- Session 过期后在后台任意页面操作，会回到登录页，并能登录后返回原页面。

### 2. 首页与后台时间实时更新
- 当前首页 Clock 只在 React render 时读取一次时间，不会持续走。
- 后台顶部时间同样只在 render 时生成。
- 首页至少每分钟刷新；如果保留秒，则每秒刷新。
- 后台时间可选择：
  - 正确实时刷新；
  - 或直接移除，避免无意义刷新。

### 3. Start 页“/”快捷键
- 搜索框显示 `/` 快捷键提示，但当前没有实际绑定。
- 增加全局键盘事件：
  - `/`：聚焦搜索框；
  - `Esc`：清空搜索 / 关闭文件夹弹窗；
  - 输入框获得焦点时不重复触发。

### 4. 统一错误提示
- 当前部分页面直接展示：
  - `navigation_failed`
  - `taxonomy_failed`
  - `media_failed`
  - `auth_failed`
  - 等内部错误码。
- 增加统一 Error Mapper。
- 用户界面显示明确中文提示。
- 如需保留原始错误，放到可展开“详细信息”中。

### 5. 统一 Toast
- 当前“已保存 / 已删除 / 已复制 / 导入成功”等提示实现分散。
- 建立统一 Toast：
  - success
  - warning
  - error
  - info
- 默认 3～5 秒自动消失。
- 支持手动关闭。
- 避免页面内长期残留“已保存”。

### 6. 统一确认与输入弹窗
逐步替换：
- `window.confirm`
- `window.prompt`

优先覆盖：
- 删除文章
- 删除导航
- 删除分组
- 删除媒体
- 删除分类 / 标签
- 恢复历史版本
- 恢复备份
- 分类 / 标签重命名

目标：
- 与 Kit 主题一致。
- 危险操作明确红色强调。
- 可显示操作影响范围。

## 非目标

这一轮不优先：
- 再新增一套新的内容系统。
- 重做整个视觉设计。
- 为了动画效果引入重型 UI 框架。
- 把 Know Me 变成复杂 CMS。

目标仍然是：
**个人主页 + 浏览器起始页 + Blog + 轻量管理后台，保持简单、顺手、可长期自托管。**
