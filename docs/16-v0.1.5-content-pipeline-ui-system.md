# Know Me v0.1.5 待办：Content Pipeline + UI System

> 基线版本：v0.1.4
> 形成方式：2026-09-20 使用 BSK 直接体验本地运行中的 `http://127.0.0.1:3000/`，覆盖公开首页、Start、Blog、文章详情、后台总览、起始页导航、文章列表、文章编辑器、分类与标签、媒体库、站点设置、备份恢复，并抽查 iPhone 14 视口。

## 目标

v0.1.5 不再继续大范围堆功能，重点完成两件事：

1. 补齐 Markdown / 文章内容流水线。
2. 统一前后台 UI 尺寸与主题系统，解决“功能能用，但整体偏小气、部分交互控件过小”的问题。

版本建议名称：

`v0.1.5 Content Pipeline + UI System`

## P0：文章内容流水线

### 1. 支持两种 Markdown 导入模式

文章编辑器的“导入 MD”需要显式选择导入类型：

- 普通 Markdown
- YAML Front Matter Markdown

当前只支持这两类，不做任意格式自动猜测，避免误解析。

Front Matter 示例：

```md
---
title: 数据库系统概念Day01
date: 2024-06-22 00:00:00
---
# 数据库系统概念 学习笔记 Day01
```

Front Matter 导入要求：

- 解析 `title` 到文章标题。
- 解析 `date` 到文章首次发布时间。
- Front Matter 本身不得进入正文。
- 未识别字段先忽略，不阻止导入。
- 解析失败时给出明确错误，不静默按普通 Markdown 导入。

### 2. Markdown 渲染能力补全

BSK 实测当前存在：

- YAML Front Matter 被渲染到正文。
- `<sup>...</sup>` 被当普通文本显示。
- 数学公式 `$...$`、`\lim`、`\frac` 没有渲染。
- TOC 会直接出现 `<mark>等价代换法</mark>` 这样的原始标记。
- 导入正文中的 H1 与文章标题形成双 H1。
- Blog / 首页摘要也被 Front Matter 和原始 Markdown 语法污染。

待处理：

- 支持 GFM 常用语法。
- 支持受控的 Markdown 内联 HTML，至少覆盖现有文章使用到的 `sup`、`mark`。
- 增加数学公式渲染，建议使用 KaTeX。
- TOC 从渲染后的纯文本标题生成，不保留 HTML 标签。
- 文章详情正文应避免和文章标题重复出现两个 H1。
- 摘要统一从“清理后的 Markdown 正文”生成，不直接截原始 source。
- 编辑器实时预览与公开文章详情必须共用同一套 Markdown pipeline，禁止两套行为漂移。

### 3. 文章时间模型补全

增加明确的文章时间语义：

- 首次发布时间：可手动编辑。
- 最后编辑时间：自动维护。
- 定时发布时间：保留现有 scheduled 语义。

建议字段语义：

- `first_published_at`
- `updated_at`
- 现有 `published_at` 继续用于当前公开/定时逻辑，或在迁移方案中明确收敛。

要求：

- 草稿首次创建不自动生成首次发布时间。
- 第一次发布时，若未手填则取当前时间。
- Front Matter 的 `date` 导入时映射为首次发布时间。
- 后续编辑默认不改变首次发布时间。
- 编辑页允许修改首次发布时间。
- 文章详情页同时显示首次发布与最后编辑时间，避免只显示一个含义模糊的日期。

### 4. 修复首次保存 / 离开页面提示

需要专项复现用户截图中的浏览器“重新加载此网站？”提示。

验收要求：

- 首次保存文章本身不触发离开确认。
- 保存成功后 dirty 状态立即清除。
- 只有真正存在未保存改动并离开/刷新时才提示。
- 自动保存、本地草稿、服务端保存三个状态不能互相误判。

## P1：Blog 与阅读体验

### 5. Blog 列表接管 Ctrl/Cmd+F

BSK 实测在 Blog 列表页按 `Ctrl+F` 后焦点仍停留在 BODY，当前没有接管。

要求：

- Blog 列表页：`Ctrl+F / Cmd+F` 聚焦站内文章搜索框，并阻止浏览器默认查找。
- 文章详情页：保留浏览器默认 `Ctrl+F`，方便查找当前文章正文。
- 已在输入框/编辑器内时不要抢快捷键。

### 6. 文章详情页视觉与主题

文章详情页需要真正使用主题 token，而不是只保证外壳跟主题变化。

统一覆盖：

- 页面背景
- 文章容器
- 标题和 meta
- 正文 H1-H6
- 链接
- blockquote
- code / pre
- table
- hr
- mark
- sup
- KaTeX
- 图片
- TOC
- 上一篇/下一篇或返回入口

阅读体验目标：

- 正文主体保持约 16px 或更高，不需要盲目放大。
- 控制正文最大阅读宽度，避免超长行。
- TOC 不要过窄、过小。
- meta 信息至少 12-13px。
- 深色主题下正文、代码块、引用块都要有正确对比度。

## P1：后台 UI System

### 7. 建立统一后台尺寸 token

BSK 实测发现“整体小气”不是页面空间不足，而是多个页面的次要控件被压得过小。

实测例子：

- 后台总览“退出登录”：约 10px 字号。
- 起始页导航行操作：约 9px 字号，↑/↓ 按钮宽约 16px。
- 文章列表搜索框：高度约 23.6px。
- 文章编辑器工具栏：约 10px / 24.4px 高。
- 分类标签行操作：约 9px / 22px 高。
- 站点设置 Tab：约 11px / 32px 高。

对照页：

- 媒体库搜索框约 16px / 39px。
- 媒体库排序控件约 16px / 41px。
- 分类新增输入框约 16px / 41px。
- 备份下载按钮约 16px / 37px。

因此不要全站粗暴“字体 +2px”，而是统一组件 token：

- 普通输入框：建议 38-42px 高。
- 普通按钮：建议 34-40px 高。
- 紧凑次要按钮：也不应低于约 32px。
- 正文控件字号：13-16px。
- 辅助文字：至少 12px。
- Tab：至少 13px，点击区域 36px 以上。
- 触屏按钮目标进一步放大。

需要统一的组件：

- Button
- Input
- Select
- Textarea
- Tabs
- Toolbar
- RowAction
- Card
- EmptyState
- Chip / MultiSelect
- Modal

### 8. 起始页导航管理页重做行操作区

当前每行 64px 高度其实足够，但操作区被压在最右侧。

建议：

- 保留拖拽手柄。
- ↑/↓ 作为辅助可访问排序方式，但尺寸正常化。
- 主操作保留“编辑”。
- 删除等危险/低频操作可以放“更多”菜单。
- 名称、URL、尺寸、可见性形成稳定列，不要互相挤压。
- 长 URL 省略显示，hover/title 查看完整值。
- 图标和名称成为视觉主层级。

### 9. 导航编辑弹窗分组

当前名称、类型、URL、父文件夹、尺寸、图标、图标文字、背景色、可见性、打开方式共十余项同一层级。

改为三块：

- 基础信息：名称、类型、URL、父文件夹。
- 外观：尺寸、图标、图标文字、背景色，并提供即时卡片预览。
- 行为：可见性、打开方式、浏览器本地属性。

### 10. 文章列表工具栏

当前搜索、状态筛选、数量、新建按钮层级弱。

改为统一 Toolbar：

- 左侧：搜索。
- 中间/次级：全部、已发布、草稿、定时。
- 右侧：数量和新建文章。
- 搜索框提高到正常后台控件高度。
- 空状态给出“新建文章 / 导入 Markdown”直接入口。

### 11. 文章编辑器布局

当前桌面双栏能用，但属性侧栏压缩主编辑区；手机端能单列，但工具栏触屏目标仍太小。

建议：

- 工具栏统一到正常按钮尺寸。
- 发布 / 分类标签 / SEO 作为可折叠属性栏。
- 增加“专注编辑”模式，隐藏右侧属性栏。
- Markdown 与预览可以支持：
  - 并排
  - 仅编辑
  - 仅预览
- 手机上默认单栏，工具栏至少 36px 点击高度。

### 12. 分类与标签交互统一

分类/标签管理页的新建输入已经是合适尺寸，行操作需要跟上。

同时重做编辑器里的分类/标签选择器：

- Chip 样式统一。
- 支持搜索已有项。
- 支持直接创建。
- 已选项删除动作更清晰。
- 下拉层宽度、阴影和选中态接入主题。
- 不要继续使用看起来像浏览器默认控件的预选框。
